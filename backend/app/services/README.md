# Services

Application/use-case logic that orchestrates models and the engine. `queue_service.py` bridges the pure engine to the database — `recompute_provider()`/`recompute_all()` load a provider's current state, call `app.engine.run()`, and persist the result (estimates, auto-no-shows, `ETA_CHANGED` events). `lifecycle_service.py` validates and applies each state transition (check-in, start, delay, complete, no-show, cancel, priority), writes the audit `QueueEvent`, and calls `recompute_provider()` afterward. `events_bus.py` is a tiny in-process publisher lifecycle actions call after each change, for Module M7's SSE stream to subscribe to later. Booking and walk-in creation are Module M3/M4, not yet implemented. Services never talk to FastAPI directly.
